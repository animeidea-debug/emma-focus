## 当前边界

本地与 Work 模型都只生成候选。严格校验通过后，结果仍必须以
`pending_review` 状态等待家长在 Admin 中审核并确认。模型、Skill、提示词和
无人值守任务没有生产写权限，也不接收 PIN。

时间边界以视频可见 OSD 为主。空房间、成人单独出现、遮挡和身份不确定区间都
是 `UNOBSERVED`，不得作为 stage 写入。成人仅在场不等于 Coaching；只有确认
直接辅导才可使用 Coaching。

## 已验证的技术结论

- 本地 Apple Silicon 环境可以运行量化视觉模型进行多图粗观察；
- 等比例缩放和小组多帧输入比强制方形拉伸更稳定；
- 人物身份、直接辅导、主动屏幕交互和基础活动应拆成窄观察，由 Python 按规则
  聚合，而不是要求模型一次产生最终类别；
- OSD 缺失、倒退或大观察缺口必须中止候选或拆分复核；
- 本地模型对身份、Screen、Coaching 和 Eye Rest 仍会出现系统性误差，因此自动
  提交保持关闭；
- 模型升级不是自动提准保证。第二模型或云端模型只用于低置信度片段复核。

## 可重复基准协议

使用 Git 外、经家长审核的多日样本。每次记录：

- 模型与量化版本、依赖版本、参数和视频/结果哈希；
- 抽帧数、分组数、耗时和峰值内存；
- 身份、类别和边界误差；
- Focus、Distractions、Tokens 和 Rating 是否与人工审核一致；
- 失败原因，以及是否产生 `pending_review` 而非生产写入。

不得将样本日期、真实时间线、视频路径、截图、原始结果或家长更正提交到 Git。

## Work 项目配置

- 使用仓库级 `emma-review` Skill；其 canonical directive 为
  `skills/emma-review/references/audit-prompt.md`；
- Work 只处理用户明确授权的单一视频任务；
- 视频上传、外部保留和供应商策略需由家长明确确认；
- 交接时只提交本文件中的规则变更，不提交实际审计产物。

## 未决项

- 多日人工基准是否足以缩小复核范围；
- 低置信度片段的云端复核供应商、成本与保留策略；
- 缓存、状态机和 Pushover 完成通知的验收；
- 服务端 pending-review 与家长批准令牌的实现时机。
